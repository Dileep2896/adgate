- @adgate/schemas (zod 4) is the API contract: import schemas and their z.infer types from '@adgate/schemas' (named exports, one module per responsibility under packages/schemas/src). CONTRACT_SCHEMAS lists every schema that has a JSON Schema file in packages/schemas/json/<Name>.schema.json; regenerate with `pnpm --filter @adgate/schemas gen:json` (json-schema.test.ts fails when a file is stale, and the directory is prettier-ignored). - Policy engine (S05): POLICY_RULES (the seven docs/policy.md rules in order), PolicyRule, PolicyDecisionResult, PolicyDecision {rule, result, detail?} and CapState {session_count, day_count, turns_since_last | null} are Zod schemas in packages/schemas/src/policy-decision.ts and registered in CONTRACT_SCHEMAS (S14's AuditRecord.policy_decisions must be z.array(PolicyDecision)). evaluatePolicy({ classification, user, policy, capState, surface }) -> { allowed, reason, decisions } lives in packages/core/src/policy/evaluate.ts (pure; the gateway reads capState from cap_state and passes it in; turns_since_last is null until the first ad in a conversation). EU expansion: packages/core/src/policy/eu-members.ts (EU_MEMBER_STATES) and regions.ts (expandRegions, isRegionAllowed). The engine does NOT read policy.sensitive_detection (the classifier applies it when merging rule and LLM sensitive signals) and always records competitor_exclusions as pending (mediation resolves it against advertiser_domain). evaluate-purity.test.ts fails if anything under packages/core/src/policy imports node:*, the gateway or an I/O library.

## 2026-09-02 S04 PolicyConfig schema, YAML loader, policy hash
Built: packages/schemas: policy-parts.ts (default-free leaf schemas PolicyTier, PolicyRegion, PolicyThreshold, PolicyCap, PolicyRetainDays, AdvertiserDomain, SensitiveDetection, DisclosureLabel/Position/Style, AffiliateNetwork), policy.ts (FrequencyCaps, Disclosure, Privacy, Regions, DemandEntry, PolicyConfig with every docs/policy.md default, PolicyConfigInput), policy-overrides.ts (DemandEntryOverride, PolicyOverrides, OverrideRejection), policy-loader.ts (PolicyValidationError, parsePolicy, parsePolicyYaml). EvaluateRequest.policy_overrides tightened from a loose record to PolicyOverrides. PolicyConfig and PolicyOverrides registered in CONTRACT_SCHEMAS (30 JSON files now). packages/core: canonical/canonicalize.ts, canonical/sha256.ts, policy/hash.ts (policyHash), policy/load.ts (loadPolicyFromYaml), policy/merge.ts (mergeOverrides); scaffold packageName export removed; PolicyValidationError re-exported. fixtures/canonical-json.json added. Tests: schemas 114 (65 new), core 59.
Decisions: Split keeps the dependency direction schemas <- core: schemas owns validation, defaults and YAML parsing (the `yaml` package lives in @adgate/schemas, matching docs/architecture.md "PolicyConfig loader"); core owns canonicalize, policyHash, loadPolicyFromYaml (= parsePolicyYaml + policyHash) and mergeOverrides. Defaults: version is z.literal(1) defaulting to 1; app_id is required and is a free non-empty string (docs use slugs like my-chat-app, not the app_ prefixed AppId); demand defaults to the four documented entries, affiliate entries require network (no default), enabled defaults true per entry; all defaults are factories so every parse returns fresh objects. Validation: z.strictObject at every level; blocked_categories values are SensitiveCategory (the suppress reason sensitive_category:<name> only exists for the sensitive taxonomy); regions.allow matches /^[A-Z]{2}$/ (EU matches, no ISO list check, same rule as User.region); empty serve_to_tiers and regions.allow are accepted (serve nobody = fail closed). JSON Schema: PolicyConfig and PolicyOverrides carry additionalProperties:false (json-schema.test.ts permits it for those two only) plus `contains: {const: self_harm}` and an if/else allOf for the two refinements. Errors: parsePolicy, parsePolicyYaml and loadPolicyFromYaml throw PolicyValidationError with issues [{path, message}] (dotted paths, [n] for indexes, '' for root) and a message "Invalid policy:\n  - path: message"; YAML syntax errors become one root issue prefixed "YAML syntax: ". YAML 1.2 core schema: `yes` stays a string, duplicate keys, multi-document and empty documents are errors. policy_hash = "sha256:" + sha256(canonicalize(policy)) with no re-parse, so only pass fully defaulted PolicyConfig values (parsePolicy, parsePolicyYaml and mergeOverrides outputs). Canonical JSON: hand-assembled string (JSON.stringify per scalar), keys sorted by UTF-16 code unit at every depth (RFC 8785 order; integer-like keys stay lexicographic), undefined properties dropped, any non-JSON value (NaN, Infinity, Date, Map, bigint, function, undefined array element) throws TypeError. Golden: the docs default policy for app_id my-chat-app hashes to sha256:f7443a7f6a44e611bf4deb2d6517341e680f3bae153e7bb3f805ac1d6c0603ae (pinned with its canonical string in packages/core/src/policy/hash.test.ts). mergeOverrides (tighten only, equal values are silent no-ops, inputs never mutated): serve_to_tiers and regions.allow are intersected with the stored list and items the override would add are rejected while its removals still apply; allow_paid_tiers true->false applies and filters serve_to_tiers to free, false->true rejected; blocked_categories and competitor_exclusions are unioned in stored-then-override order, never rejected; sensitive_detection balanced->strict only; min_commercial_intent and min_confidence up only; per_session and per_user_per_day down only; min_turns_between UP only (more turns between ads is stricter, even though docs say "lower caps"); demand entries with enabled:false disable matching stored entries (affiliate without network matches every affiliate entry), enabling a disabled source or naming one the policy lacks is rejected; privacy.store_raw_text true->false only; version, app_id, disclosure.* and privacy.retain_days are per-app settings and any change is rejected. Rejection paths are dotted (frequency_caps.per_session, demand[1]); these become override_rejected notes in the audit story. mergeOverrides takes an already validated PolicyOverrides (EvaluateRequest validates it) and does not re-validate. Shared test fixtures live in non-test modules (packages/schemas/src/policy.fixture.ts, packages/core/src/policy/merge.fixture.ts) because importing a *.test.ts re-registers its tests in the importer. Dependencies added: yaml ^2.9.0 in @adgate/schemas (YAML 1.2 parser, zero deps, actively maintained; needed for parsePolicyYaml); @adgate/schemas workspace:* in @adgate/core (pnpm add writes workspace:^, normalised by hand to workspace:* per the convention).
Gotchas: zod 4 `.default(value)` hands back the same object on every parse, so object and array defaults must be factories. `.partial()` on a schema whose fields carry defaults still fills them in, which is why PolicyOverrides is built from default-free leaf schemas instead of PolicyConfig.partial(). zod 4 runs superRefine only when the shape has no structural issue (missing key, wrong type); value issues (ranges, patterns) co-report with the refinement issues, so tests must not expect the self_harm issue next to a missing key. Function-form defaults on a discriminated-union array need an explicit return type (`(): DemandEntry[] =>`) or TS widens the literals. Object.keys enumerates integer-like keys first, so canonical JSON cannot be JSON.stringify over a re-keyed object. `printf '%s' '<canonical json>' | shasum -a 256` derives golden hashes without a build. Prettier changed line wrapping in eight files after the first write; run it before the gates.
Ideas: a defaultPolicy(app_id) helper; validate regions.allow against the ISO 3166 list and add the EU member-state expansion the policy engine needs; a root `pnpm gen:json` alias; deduplicate list fields inside PolicyConfig; the audit story can reuse sha256Prefixed and canonicalize for record_hash and content_hash.

## 2026-09-02 S05 Policy engine
Built: packages/schemas/src/policy-decision.ts (POLICY_RULES, PolicyRule, PolicyDecisionResult pass|fail|pending, PolicyDecision, CapState; PolicyDecision, PolicyRule and CapState registered in CONTRACT_SCHEMAS, 33 JSON files now). packages/core/src/policy: eu-members.ts (EU_MEMBER_STATES, isEuMemberState), regions.ts (EU_REGION_TOKEN, expandRegions, isRegionAllowed), evaluate.ts (evaluatePolicy, EvaluatePolicyInput, PolicyEvaluation), evaluate.fixture.ts (serveInput, defaultPolicy, SERVE_CLASSIFICATION, FREE_US_USER, FRESH_CAP_STATE, CHAT_SURFACE). Tests: evaluate.test.ts (order, first failure wins, tiers, blocked categories, thresholds, competitor pending, surface), evaluate-caps.test.ts (every cap at its boundary), evaluate-purity.test.ts (import grep), regions.test.ts (EU data, expansion, region rule). Totals: schemas 121 tests (+7), core 110 (+51).
Decisions: Rules run from a Record<PolicyRule, RuleCheck> iterated in POLICY_RULES order; every rule appends exactly one decision and reason is the first fail. Pass entries carry no detail except frequency_caps, which always renders `session=<n>/<cap> day=<n>/<cap> turns_since=<n>` (day=n/a without user_hash, turns_since=none when null) so the docs/audit.md example is reproduced byte for byte; fail entries carry a short detail (tier=paid not in serve_to_tiers, tier=paid requires allow_paid_tiers, region missing, region=BR not in regions.allow, health in sensitive / health in categories, confidence=0.69 min=0.7, commercial_intent=0.59 min=0.6). competitor_exclusions is always { rule, result: 'pending' } with no detail. Details never contain message text. serve_to_tiers re-checks allow_paid_tiers for any non-free tier on top of the schema guarantee (CLAUDE.md non-negotiable). regions: EU expands to the 27 member states (ISO codes, GR not EL); a missing user.region fails closed; a user.region of EU never matches because the token only has meaning inside the policy. blocked_categories iterates policy.blocked_categories in policy order and checks classification.sensitive then classification.categories as plain strings (the content taxonomy has no sensitive names today; the check is defensive as the doc requires both), appending self_harm if a hand-built policy dropped it. Thresholds use `score >= min` and caps use `count < cap` so NaN fails closed: equal to a threshold passes, equal to a cap fails, turns_since_last equal to min_turns_between passes, null passes, per_user_per_day applies only when user.user_hash is a non-empty string. policy.sensitive_detection is not read by the engine: it decides how the classifier merges rule and LLM sensitive signals into classification.sensitive, so the classifier stories own it. surface is accepted and ignored (placement is schema-enforced). evaluatePolicy never throws on typed inputs and does not try/catch malformed ones; the gateway's evaluate wrapper maps any throw to decision suppress reason error. EvaluatePolicyInput and PolicyEvaluation are TS interfaces in core (like MergedPolicy); only the shapes shared with the audit record are Zod. No dependencies added.
Gotchas: exactOptionalPropertyTypes means PolicyDecision.detail must be omitted rather than set to undefined, so decisions are built with a ternary, not a spread. Prettier's wrapping pushed the first evaluate.test.ts past 300 lines; the tests are now split by rule family. A test module that imports a *.test.ts re-registers its tests, so shared inputs live in evaluate.fixture.ts. The purity test walks relative imports from evaluate.ts and asserts the only bare specifier is @adgate/schemas; importing ../canonical (node:crypto) from the engine would fail it on purpose.
Ideas: the gateway should derive turns_since_last as current turn index minus cap_state.last_turn_index (null when no ad yet) and reset day_count on a new UTC day; a renderDecisions helper for the dashboard; validate regions.allow against the ISO 3166 list at parse time; a table-driven fixture file (fixtures/policy-cases.json) so the Python SDK can replay the same cases.
