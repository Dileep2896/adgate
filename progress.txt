## Codebase notes (maintained across iterations, edit in place)
- Docker Postgres host port is ${PGPORT_HOST:-5432} in docker-compose.yml. On this dev machine a native Postgres owns 5432, so .env sets PGPORT_HOST=5433 and both DATABASE_URL values use 5433. CI and fresh clones keep 5432. Always read the port from env, never hardcode 5432.
- CI is .github/workflows/ci.yml: ubuntu-latest, Node 20, pnpm from package.json packageManager (pnpm/action-setup@v4 with no version input), `pnpm install --frozen-lockfile`, then typecheck, lint, test. A postgres:16 service container (user/password/db adgate) listens on localhost:5432 and the job env exports DATABASE_URL and DATABASE_URL_TEST on 5432. Service containers cannot mount scripts/db/init.sql, so a psql step creates adgate_test (idempotent). Integration tests must read DATABASE_URL_TEST from the environment and truncate tables; they must not assume the compose init script ran.
- .env.example is the canonical list of env vars, one comment line per variable directly above it. When a story adds a variable, add it there with a comment (and to the CI job env if tests need it).
- LICENSE is the canonical Apache 2.0 text from apache.org (11358 bytes). Never edit it; add third-party notices in a separate NOTICE file if ever needed.
- @adgate/schemas (zod 4) is the API contract: import schemas and their z.infer types from '@adgate/schemas' (named exports, one module per responsibility under packages/schemas/src). CONTRACT_SCHEMAS lists every schema that has a JSON Schema file in packages/schemas/json/<Name>.schema.json; regenerate with `pnpm --filter @adgate/schemas gen:json` (json-schema.test.ts fails when a file is stale, and the directory is prettier-ignored). SENSITIVE_TAXONOMY and CATEGORIES_TAXONOMY live in packages/schemas/src/taxonomy.ts and must equal fixtures/classify-fixtures.json (taxonomy.test.ts enforces it); Classification.categories and .sensitive are validated against them. tsx is a root devDependency for running TypeScript dev scripts (`tsx src/foo.ts`) without a build.

## 2026-09-02 S03 Zod schemas for the API contract
Built: packages/schemas implements docs/api.md with zod 4.5.4. Modules: taxonomy.ts (SENSITIVE_TAXONOMY, CATEGORIES_TAXONOMY, SensitiveCategory, ContentCategory), common.ts (AppId, AuditId, CreativeId, Sha256Hash, IsoTimestamp, MessageRole, Message, User, SurfaceType, Surface, ErrorResponse, HealthResponse), classification.ts (ClassificationMethod, Classification), creative.ts (DemandSource, Creative), suppress-reason.ts (FIXED_SUPPRESS_REASONS, SENSITIVE_CATEGORY_REASONS, SUPPRESS_REASONS, sensitiveCategoryReason(), SuppressReason), evaluate.ts (Decision, EvaluateRequest, EvaluateResponse), events.ts (AttestRequest, EventType, EventRequest), verify.ts (VerifyCheckName, VerifyCheck, VerifyResponse), json-schema.ts (CONTRACT_SCHEMAS, toJsonSchemaObject, renderJsonSchema(s), toJsonSchema(outDir?) which writes packages/schemas/json/<Name>.schema.json), gen-json.ts (the gen:json script). 28 JSON Schema files committed. Every TS type is z.infer; index.ts re-exports all modules. 68 tests: all seven docs/api.md bodies verbatim (api-examples.test.ts), taxonomy equals the fixture, SuppressReason accepts the 7 fixed reasons plus sensitive_category:<taxonomy name> and rejects sensitive_category:unknown, EvaluateRequest rejects both messages and context_summary absent, serve/suppress consistency, JSON files byte-identical to a fresh render (verified to fail on a stale file and to be idempotent).
Decisions: zod v4 native z.toJSONSchema (target draft-2020-12, io 'input', unrepresentable 'throw'); no zod-to-json-schema. io 'input' because zod strips unknown keys instead of rejecting, so files carry no additionalProperties:false and stay forward compatible for the Python SDK. JSON files: keys sorted at every level except each `properties` map, which keeps declaration (contract) order; two-space indent; trailing newline; title equals the export name; everything inlined (no $defs) so each file is self-contained. Refinements zod cannot express are attached with .meta() and merged verbatim: EvaluateRequest anyOf required messages|context_summary, EvaluateResponse allOf if/then (serve needs creative object and null reason, suppress needs null creative and string reason). SuppressReason is one flat z.enum (7 fixed + 9 sensitive_category:<name> built from SENSITIVE_TAXONOMY) so the JSON Schema is an explicit enum; core should build reasons with sensitiveCategoryReason(name) for exact typing. Classification.categories is z.array(ContentCategory) and sensitive is z.array(SensitiveCategory), both taxonomy-enforced: the classifier story must normalise LLM output to the taxonomy (unknown category -> general, unknown sensitive flag -> treat as failure/suppress). ClassificationMethod is z.enum(['llm','rules']); prompt_version is any non-empty string; extend the enum only if an error path truly needs it. EvaluateRequest: app_id must start with app_ (prefixed ULID convention; only the prefix is checked because doc examples are elided); user.tier any non-empty string; user.region optional ^[A-Z]{2}$; locale and user_hash optional strings; messages optional but min 1 item when present; context_summary optional min 1; refine requires at least one (issue path ['messages']); surface.placement literal after_answer, max_creatives optional int >= 1 (no default, so input and output types match); policy_overrides is z.record(z.string(), z.unknown()) and S04 should tighten it to a partial PolicyConfig. Unknown keys are stripped, not rejected. EvaluateResponse keeps classification and audit_id required even for reason 'error' (the contract shows them always present): the gateway must synthesise a zeroed classification and still write an audit record on error paths. creative.url is a non-empty string, not z.url(), because the documented example https://<gateway>/c/... is not a parseable URL; Creative.body may be empty, other text fields min 1; DemandSource is direct|affiliate|koah|gravity from docs/policy.md. MessageRole is system|user|assistant|tool. IsoTimestamp = z.iso.datetime() accepts only trailing-Z UTC. Sha256Hash requires the sha256: prefix (AttestRequest.model_output_hash); user_hash stays loose because the doc example is "optional sha256". VerifyCheckName is the eight docs/audit.md checks in order. HealthResponse and ErrorResponse added beyond the story list so every api.md body has a schema. Removed the scaffold packageName export from @adgate/schemas. Dependencies added: zod ^4.5.4 in @adgate/schemas (stack list) and tsx ^4.23.13 at the workspace root so TypeScript dev scripts (gen:json now, seed and migrate scripts later) run without a build step. packages/schemas/json/ is prettier-ignored and listed in package.json files.
Gotchas: Prettier needed a second --write pass on common.ts (member-chain formatting is not idempotent on the first pass); always finish with pnpm format:check. z.toJSONSchema adds maximum 9007199254740991 to .int() and a long regex pattern to z.iso.datetime(); harmless. toJsonSchema() imports node:fs statically from the package entry; if a browser bundle ever imports @adgate/schemas at runtime, move it to a subpath export. `z.string().startsWith()` renders as pattern ^prefix.* in JSON Schema. The agent cwd resets between shell calls; use absolute paths for every file edit.
Ideas: subpath export @adgate/schemas/json-schema to keep node:fs out of the main entry; the gateway /openapi.json (S-gateway) can be assembled from CONTRACT_SCHEMAS via z.toJSONSchema with $defs; PolicyConfig (S04) and AuditRecord (audit story) should be registered in CONTRACT_SCHEMAS so they get JSON files and the staleness test; a coverage threshold for packages/schemas.
