## Codebase notes (maintained across iterations, edit in place)
- Docker Postgres host port is ${PGPORT_HOST:-5432} in docker-compose.yml. On this dev machine a native Postgres owns 5432, so .env sets PGPORT_HOST=5433 and both DATABASE_URL values use 5433. CI and fresh clones keep 5432. Always read the port from env, never hardcode 5432.
- CI is .github/workflows/ci.yml: ubuntu-latest, Node 20, pnpm from package.json packageManager (pnpm/action-setup@v4 with no version input), `pnpm install --frozen-lockfile`, then typecheck, lint, test. A postgres:16 service container (user/password/db adgate) listens on localhost:5432 and the job env exports DATABASE_URL and DATABASE_URL_TEST on 5432. Service containers cannot mount scripts/db/init.sql, so a psql step creates adgate_test (idempotent). Integration tests must read DATABASE_URL_TEST from the environment and truncate tables; they must not assume the compose init script ran.
- .env.example is the canonical list of env vars, one comment line per variable directly above it. When a story adds a variable, add it there with a comment (and to the CI job env if tests need it).
- LICENSE is the canonical Apache 2.0 text from apache.org (11358 bytes). Never edit it; add third-party notices in a separate NOTICE file if ever needed.

Decisions: All tooling devDependencies live at the workspace root only; packages declare none (pnpm exposes root bins to workspace scripts). Relative imports inside src use the .js extension (NodeNext); vitest and tsup resolve them. Tests live in src/**/*.test.ts and are typechecked by tsc --noEmit (tsconfig include: src). build = tsup src/index.ts --format esm --dts; the exports map points at dist, and turbo test/typecheck dependsOn ^build so cross-package imports resolve once packages depend on each other. pnpm test/typecheck/lint run per package through turbo; `pnpm exec vitest run` at the root runs everything via projects. ESLint bans default exports inside packages/*/src (CLAUDE.md: named exports only); tool config files are exempt. `pnpm lint` is ESLint only; `pnpm format:check` is Prettier and is a separate gate. prd.json, fixtures/, docs/ and *.md are prettier-ignored on purpose (hand-formatted, contract docs).

Built: .github/workflows/ci.yml (push + pull_request; Node 20; pnpm pinned via packageManager; frozen-lockfile install; postgres:16 service container with a psql step that creates adgate_test; typecheck, lint, test with DATABASE_URL/DATABASE_URL_TEST on 5432). Decisions: pnpm/action-setup gets no explicit version so it reads package.json packageManager (pnpm@9.15.9); bump only that field. adgate_test in CI is created with psql plus a WHERE NOT EXISTS guard and \gexec (idempotent on re-runs) because service containers cannot mount the compose init script. DATABASE_URL and DATABASE_URL_TEST are job-level env so every step, not just test, sees them. Workflow adds permissions: contents: read and a per-ref concurrency group that cancels superseded runs. No dependencies added.
Gotchas: There is no GitHub remote, so the workflow was verified locally, not on GitHub: the YAML was parsed with js-yaml (transitive dep in node_modules/.pnpm) and checked for triggers, node-version 20, service image, ports and job env; the psql step was run verbatim against the docker Postgres on 5433 after dropping adgate_test (created it, second run was a no-op, exit 0); then the exact command sequence pnpm install --frozen-lockfile, pnpm typecheck, pnpm lint, pnpm test ran green with the job env exported, and pnpm format:check passed. psql -c cannot mix SQL with \gexec, so the step feeds psql through a heredoc. zsh treats `status` as a read-only variable; do not use it as a shell variable name in scripts. Prettier formats .github/workflows/*.yml (singleQuote), so run pnpm format:check after editing the workflow. pnpm install --frozen-lockfile added four empty `packages/<name>: {}` importer entries to pnpm-lock.yaml that S01 had not committed (packages have no deps yet); committed here so CI's frozen install is stable, and a second frozen install leaves the lockfile untouched.
Ideas: add pnpm format:check as a CI step once the loop stabilises; cache turbo outputs in CI with actions/cache keyed on the lockfile; CONTRIBUTING.md and a NOTICE file when third-party code is vendored; a README badge once a GitHub remote exists.
